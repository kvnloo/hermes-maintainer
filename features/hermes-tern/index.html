01 / PRODUCT INTENT

The problem

Hermes owns a capable terminal agent, but Tern can render more than ANSI cells. A bespoke UI that duplicates session state, approvals, or tools would be costly to maintain and unsafe to evolve. We need native interaction, not a second agent.

FOR PEOPLE

Stay in flow

Write, edit, inspect tools and approve work without context switches or opaque terminal control sequences.

FOR MAINTAINERS

Keep one source of truth

Hermes continues to own sessions, credentials, models, work, approvals, tools, safety and persistence.

PRD rule: this is a proposed product contract, not a claim that every item has shipped. The fork's source-implemented features and real-host acceptance are tracked separately in RFC #510.
02 / EXPERIENCE CONTRACT

What great looks like

Five journeys from the user's point of view, each tied to a testable requirement.

01
Start anywhere

Inside a conforming Tern pane, present native content. Outside Tern or after an unsupported handshake, return to the ordinary Ink TUI. No terminal corruption or leaked TSP bytes.

02
Make every turn legible

Stream text and tools with stable identities, readable errors, accurate running and waiting states, and bounded scrollback work. No fabricated progress or duplicate submissions.

03
Keep the composer safe

Multiline, Unicode, paste, undo, history, attachments and contextual commands must preserve the user's draft. Approvals, masked prompts, clarification and interrupts remain gateway-owned.

04
Make parallel work understandable

Show parent/child subagents, background jobs, plans, model settings and activity without stealing focus. Resume and session switching must reject stale events from other owners.

05
Respect the terminal host

Dark/light themes, narrow panes, reduced motion, hidden/visible events, host focus ownership and credit/ACK backpressure should behave correctly under real Tern.

06 / DEFINITION OF DONE

What proves it works?

Separate source implementation, deterministic tests and actual terminal-host evidence.

AUTOMATED GATE

Correctness

Typecheck, Vitest, contract tests, pinned SDK/Node dependencies, artifact checks and clean Ink fallback. Native actions must never bypass Hermes authorization.

REAL HOST GATE

Native UX

Isolated Tern screenshots and end-to-end flows at 80×28, 120×36, 180×44; dark/light; reduced motion; approval, masked secret, resume, error and exit.

LATENCY GATE

Measured presentation

Record time-to-visible content, input responsiveness, frame/op counts, ACK backlog and p50/p95 frame age under matching host/version. Never infer speed from source alone.

SAFETY / GOVERNANCE

Upstream fit

No private dependency or second runtime authority, no terminal escape leaks, explicit maintainer review, attribution and compatible plugin licensing.

Promotion hold: a merged downstream code slice, passing mocked tests, and a real signed-in Tern session are different evidence levels. This page intentionally makes no claim of completed native acceptance.

08 / DECISION REGISTER

What isn't settled

A
Plugin or small in-core adapter?

Community plugin exists as an open catalog proposal; upstream frontend registration API remains a separate draft. Avoid promoting both paths without a boundary decision.

B
Which changes are actually new?

Don't duplicate native transcript, approvals, subagents, PR dock or process charts that the plugin already advertises. Pin implementation and compare behavior.

C
Which platform capabilities may be trusted?

Version and validate session-scoped UI capabilities and plugin RPC/event boundaries; don't rely on unchecked file markers or hidden global state.

D
How do we avoid introducing new security risks?

Review plugin command middleware, TERN_PANE propagation, image data ownership, secrets/approvals, and the typed-versus-pasted shell-command distinction.
