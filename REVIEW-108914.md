## What this actually is

Tek shipped the **self-hosted Linux gateway + Hermes Desktop** half of “a bot has a screen you can take over.”

That is a real product: per-profile TigerVNC `Xvnc` (Unix socket, 0600, no TCP) + Xfce under a private dbus session, a disk lease with fcntl, a server-side RFB input filter, `/api/display/ws` ticketed off the already-authenticated `/api/ws`, Desktop Take over / Hand back, install-from-Desktop via the existing sudo card, and `computer_use` refused with `code: human_has_control` while a human holds.

- Nous-hosted / cloud headed sessions (PTY + WebVNC + CUA on one remote display) — that is #108592 / PER-1430
- hosted **browser** noVNC for login/CAPTCHA — that is #92524

- a security boundary (docs say this; the lease does not)

## Must-fix on this SHA (P1)

Independently reproduced against the checkout at `d947fc8`.

### P1-1 — Windows `computer_use` is broken even with Bot Screen off

`handle_computer_use` always imports `tools.computer_use.handoff`, which imports `tools.bot_desktop.lease`, which does `import fcntl` at module load.

Probe: patch `__import__` so `fcntl` raises `ModuleNotFoundError`, then `handle_computer_use({'action': 'capture'})` raises `No module named 'fcntl'` before any backend.

Reported by helix4u, confirmed by MrD1az / iamlukethedev / Xipong. Still true on this head. This is a merge blocker for a cross-platform tool.

Gate the Linux lease behind `sys.platform` (or a portable lock) **before** the import. Add a regression that capture still works when `fcntl` is missing.

### P1-2 — Watcher can OOM `hermes serve` via ClientCutText

`RfbClientFilter._message_length` trusts the declared clipboard length. `feed()` grows `_buf` with no cap. A viewer who **never held the lease** can declare `0x7FFFFFFF` and stream body bytes forever.

Probe on this SHA: after handshake, 64 × 64KiB → `_buf` is 4,194,312 bytes, nothing forwarded, socket still open.

Reported by carlotestor, confirmed by helix4u / iamlukethedev. Cap declared clipboard length (TigerVNC’s ~1MB default is enough) and overall `_buf`; `ValueError` already maps to close 1003.

### P1-3 — Local real-profile CDP browsers skip the lease fence

`_shares_bot_desktop_browser` returns false whenever `cdp_url` is set. This PR also launches local real-profile headed Chromium with the Bot Desktop env (`browser_tool_real_profile.py`). Those sessions are CDP **and** on the same DISPLAY the human is typing into.

Tek’s round-2 fence (`test_bot_desktop_browser_fence.py`) only covers agent-browser `--session` (no `cdp_url`). Julien’s original P1 is fixed for that path; the real-profile hole is still open.

Fence by **local launch provenance**, not “has cdp_url”. Keep the exemption for unrelated remote / user-attached CDP. Remote Browserbase-style CDP is not on the bot seat — that exemption is fine; the hole is local CDP on the same DISPLAY.

### P1-4 — Epoch discard happens after screenshot persist and aux-vision

`handle_computer_use` compares epoch **after** `_dispatch` returns. Capture dispatch calls `_capture_response` → `_capture_view`, which calls `_persist_capture_image` and may `_route_capture_through_aux_vision` **inside** dispatch.

Returning `human_has_control` cannot retract the image already on disk or already sent to auxiliary vision.

MrD1az F1. Check epoch before persist / vision; keep the outer fence as belt-and-braces.

### P1-5 — In-flight input can still hit the seat after Take over

Epoch discard drops the **tool result**. It does not cancel an already-running click/type. helix4u: acquisition acknowledges human control without waiting for in-flight actions to stop. Source-true on this SHA. Either cancel at the backend boundary, or do not confirm “You are in control” until admitted actions can no longer affect the screen. A design note + test is the minimum if full cancel is hard.

## What is genuinely good (so the P1s don’t bury it)

- On-disk lease + epoch is the right architecture for serve / gateway / CLI not sharing memory. Cross-process test is real.
- Server-side RFB filter (not noVNC `viewOnly`) is the load-bearing input gate. carlotestor’s extra probes show framing holds; the hole is size, not type confusion.
- 1006 / abort keeping HUMAN is the correct control-theory after Julien. The new 1005 bug is the cost of that fix plus noVNC’s `close()`.
- Ticketed `/api/display/ws` off authenticated `/api/ws`, Unix socket 0600, no TCP, `-SecurityTypes None` only behind the gateway — coherent for a single-user gateway. Not coherent as a multi-user security boundary (and docs say so).
- Sudo password on the requesting connection, empty cancel, one install per profile — that round-1 P1 looks actually fixed.
- Scope honesty in the body (Related not Closes, auto_start off, request_handoff does not send Telegram) is rare and correct.
- Live Xvnc/Xfce evidence in the body is more than most PRs of this size.

This is a serious piece of product engineering. It is not merge-ready on `d947fc8`.
